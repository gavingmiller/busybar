# busybar

Custom apps for the [BUSY Bar](https://busy.app) HTTP display API.

## Prerequisites

- [Bun](https://bun.sh)
- A BUSY Bar, connected to your computer via USB

## Getting hello-world working

1. Install dependencies:

   ```sh
   bun install
   ```

2. Connect your BUSY Bar to your computer via USB. No authentication is
   needed over USB — the device is reachable at `10.0.4.20`.

3. Run the app:

   ```sh
   bun run hello-world
   ```

   You should see "Hello, World!" centered on the BUSY Bar's front display.

## Other apps

- **nyan-cat** — pixel-art Nyan Cat on the front display. `src/nyan-cat/
  sprite-data.ts` holds the cat's pixel art (26x12, four run frames) as
  plain ASCII-grid literals, meant to be hand-edited with an external pixel
  editor rather than by hand. The rainbow trail is generated by
  `src/nyan-cat/trail.ts` (six bands on a gentle travelling sine wave, one
  column left per frame) — the hand-drawn `TRAIL_FRAMES` in sprite-data.ts
  are no longer drawn.
  - `bun run nyan-cat:stationary` — draws once, centered, stays put (legs in
    their neutral pose, trail as a single static frame).
  - `bun run nyan-cat:flying` — loops it flying across the screen; Ctrl+C to
    stop (clears the display on exit).
  - `bun run nyan-cat:rainbow` — the whole front display as one scene
    (`src/nyan-cat/sky.ts`): a star field scrolls right-to-left behind the
    cat, which runs in place (a 4-frame leg cycle) while the rainbow trail
    waves behind it. Two native looping `.anim` layers (96 frames at 16 fps,
    the smallest loop that closes for trail, legs and stars together): the
    star field, and the cat with a display-width trail in front of it. The
    control server (below) then "pans the camera": at random intervals the
    cat falls behind (drifts left 8–24 px over ~2 s), hangs there, and
    catches up — `src/nyan-cat/pan.ts`, driven by upserting just the cat
    layer's x, which the firmware does without restarting its playback (`src/lib/anim-file.ts` encodes the
    device's `.anim` format, uploaded via `POST /api/assets/upload`) — the
    device plays/loops it forever on its own, no ongoing process, nothing to
    Ctrl+C. Composited in software (trail painted onto a `Canvas`, cat
    painted on top of the *same* canvas) rather than sent as two separate
    elements, because the device doesn't composite transparency between
    layered elements — see `sceneAnimationFrames`/`nyanCatElements` in
    `src/nyan-cat/sprite.ts`.
- **color-grid** — a systematic 72-swatch reference palette for checking how
  a given color actually renders on the physical LED matrix before using it
  elsewhere: 12 hues (30° apart) crossed with a 3-step brightness ramp and a
  2-step saturation ramp, plus a 12-step grayscale ramp.
  - `bun run color-grid` — draws the grid and prints the row/column key.

- **scenes** — pre-rendered full-display loops the bar plays natively
  (`src/scenes/<name>/`, each exporting a `Scene` from `src/lib/scene.ts`:
  id, name, fps and `frames()` returning one seamless 72x16 RGBA loop).
  `runScene` encodes the loop once, uploads it under a content-hashed file
  name unless the device already holds it, draws it looping, then drops that
  scene's stale renders. Ported from the community gallery
  (github.com/maxswinkels/busybar-apps), whose versions redraw from the host
  over HTTP a few frames a second: Lava Lamp (`lava_lamp`), Matrix Rain
  (`matrix_rain`) and Aquarium (`aquarium`). Register new ones in
  `src/scenes/index.ts`; the control server lists them automatically.
  `munchers-run` — the Number Munchers characters (ported from that
  project's sprite sheets by `extract-art.py`) and a chicken sprint across
  a fixed ground, entering and leaving at random. Each character's art is
  settled by putting five numbered candidates on the bar at once via the
  `picks` scene (`munchers-run/picks.ts`, "Character Picks") and letting
  Gavin choose; the winner moves into `art/<name>.ts`. It is a debug tool:
  flagged `debug`, so the control page and Shuffle skip it, but
  `POST /api/apps/picks {"on":true}` still shows it.

  Scenes can be seasonal: `available(now)` on the scene (see `sleigh`, Santa's
  Sleigh, December only on the Edmonton calendar) hides it from the control
  page and from Shuffle out of season, and switching it on then answers 409
  with "Santa's Sleigh only plays in December". Omit it and the scene is
  always offered.

- **server** — a small always-on control server (`127.0.0.1:7495`, loopback
  only) with a web page that turns every app on the bar on and off: each
  Nyan Cat flavour (`src/nyan-cat/flavours.ts` — the classic cat and a
  purple-frosting one, same pixel art with colour keys swapped, each with
  its own cat-layer asset), every registered scene, plus each JS app the
  bar reports as installed. Pantheon embeds it as its "BUSY Bar" tab, so
  the toggles live in the hub; the page re-reads the list every 10 s and
  when the tab comes back into view, and shows the next shuffle change as a
  countdown ("in 1 hr 10 min"). One thing shows at a time, so turning
  anything on first quits the running JS app and clears every draw.
  - `bun run server` — run it by hand (`BUSYBAR_CONTROL_PORT`,
    `BUSYBAR_BASE_URL` and `BUSYBAR_STATE_FILE` override the defaults).
  - `git config core.hooksPath .githooks` once per clone: the versioned
    pre-push hook runs the whole suite and refuses to push a red tree.
  - `bun run install-launchd` — installs `launchd/com.busybar.server.plist`
    into `~/Library/LaunchAgents` (KeepAlive, starts at login, logs to
    `~/Library/Logs/busybar/server.log`). The repo copy is the source of
    truth; edit it there and re-run.
  - `GET /` — the control page (Light / Dark / System theme, hidden inside
    Pantheon where it follows `prefers-color-scheme`).
  - `GET /api/apps` → `{ "apps": [{ "id", "name", "kind": "draw" | "js",
    "state": "on" | "off" | "unknown" }], "changedAt": <UTC ISO Z> }`. The
    device has no endpoint that reports what it is showing, so the states
    come from the last command the server successfully sent, persisted in
    `~/Library/Application Support/busybar/state.json` (`unknown` until the
    first command, or after a firmware update reboots the bar).
  - **Shuffle** is a global switch above the app list: while it is on, a
    different animation plays every 2 hours — Nyan Cat and every scene —
    dealing each one once per round before any repeats
    (`src/server/shuffle.ts`). The animation currently dealt shows as the
    one that is on. Picking an animation by hand keeps shuffle on (that
    pick becomes the current card and the clock restarts); launching a JS
    app or turning the bar off switches it off. The round (remaining deck,
    next change) lives in the state file, so a server restart re-arms the
    timer for the remaining time and a missed change fires at once; a
    failed change is retried a minute later. `GET /api/apps` carries
    `shuffle: { on, nextChangeAt }`; `POST /api/shuffle` with
    `{ "on": true | false }` flips it.
  - `POST /api/apps/<id>` with `{ "on": true }` runs `nyan-cat:rainbow` for
    `nyan_cat` (and starts its camera pan, which the server keeps running
    until anything else is turned on), `runScene` for a scene id, or
    `POST /api/apps/launch` for a JS app; `{ "on": false }` quits / clears. A device failure answers 502 and
    leaves the stored state alone.

## JS apps (run on the bar itself)

Since firmware 1.3.1 the bar runs JavaScript apps natively (JerryScript,
HTTP API 27.12+). They live under `js-apps/<app id>/`, one folder per app,
scaffolded with [busy-tools](https://github.com/busy-app/busy-tools) and
built/installed with `busy-cli`. Node 24 is required (`.nvmrc` in each app).
Unlike the Bun apps above, nothing runs on the Mac once an app is installed:
the bar keeps it in its APPS menu and runs it on its own.

- **js-apps/app.gavin.ravens** — *Ravens*. Huginn and Muninn (9x7, chosen
  from a Character Picks size line-up on 2026-11-09; perched 7x6) flap across a
  starry night sky at different speeds and heights, so they cross and overtake
  each other. The sky scrolls in parallax: Dino Run's three clouds (its 9x3
  cloud sprite on the same 144 px loop) drift left at half a pixel a tick,
  while the stars stay put: each one fades in, shines for 6–22 s, fades out,
  and is reborn somewhere else after a dark pause.
  - **OK** (short press) — Muninn lands bottom-left and a line from the
    Hávamál scrolls past, then he takes off again.
  - **Start** — switches between the night and dawn palettes.
  - **Back** — exits (clears the display, stops every timer).
  - Build and run from the app folder: `npm install`, `npm run typecheck`,
    `npm run build`, then `npm run app:install` and `npm run app:run` with the
    bar on USB (`npm run app:stop` / `npm run app:uninstall` to undo), or over
    Wi-Fi the way `gavin.dino_run/build.sh --install` does: `POST /api/apps/quit`,
    `POST /api/apps/stage` with the tgz, `POST /api/apps/install?install_key=…`. The
    sprites are XPM2 bitmaps built in `src/sprites.ts`; the lines are in
    `src/havamal.ts`. `src/appmeta/icon_front_8x8.png` is the menu icon.
    The raven is traced from the sixth sprite of an itch.io raven sheet
    Gavin picked (the first flying pose), five flap frames shrunk to 14x11,
    with the sheet's standing pose (10x8) for the perch; beak and feet are
    yellow.
- **js-apps/gavin.dino_run** — *Dino Run*, as a stand-alone animation. The
  community [Dino Run](https://github.com/alexseminoisok/busybar-dino-run)
  endless runner with the game taken out: the dino is already running when
  the app starts, an autopilot simulates the game's own collision model one
  jump ahead over every obstacle and jumps or ducks on its own, there is no
  title screen, score or game-over screen, and the speed never changes.
  The obstacle pool still unlocks level by level with distance run (birds,
  bigger cacti), so the variety progresses like the game's. A (rare) hit
  just stumbles for a moment and keeps going. **Back** exits. Nothing of
  the game is vendored: `build.sh` downloads the upstream release package,
  `patch.py` rewrites `scripts/main.js` and the manifest, and
  `./build.sh --install` quits the running app, then stages and installs
  the result on the bar over USB. Needs `gh` and Python 3.

### Shared code

`src/lib/` holds the rendering/animation pipeline every app is built on top
of — not an app itself, nothing to run directly:

- `display.ts` — the `RectangleElement` type, device color/positioning quirk
  compensation, display dimensions, draw priority.
- `canvas.ts` — a pixel buffer to draw onto (`setPixel`/`fillRect`/
  `paintGrid`), compiled to the fewest `RectangleElement`s the device needs
  (row run-length + vertical merge). This is the image rendering library —
  every visual app builds a `Canvas`, draws onto it, then calls
  `toElements()`, rather than hand-placing rects.
- `busybar-client.ts` — the draw/clear HTTP calls, including `drawFrame()`
  (clear everything, then draw — see below).
- `animate.ts` — the animation library, built on `canvas.ts` +
  `busybar-client.ts`: `runAnimation()` clears, then repeatedly calls a
  `frameFn(tick)` on an interval and draws the result; `installShutdownHandler()`
  wires Ctrl+C to stop the loop and clear the display. Best for animations
  where the shape drawn doesn't change id-to-id between frames (e.g. a
  sprite that only translates, like flying nyan-cat) — an animation whose
  element ids do shift frame to frame should use a native `.anim` asset
  instead (see below), not this loop, to avoid a visible flash to the
  device's own idle app during the gap between clear and redraw.
- `anim-file.ts` — encodes the device's native `.anim` binary animation
  format (reverse-engineered from the public firmware source,
  `github.com/busy-app/busybar-firmware`, `lib/anim_file/anim_file_format.h`
  — undocumented in the OpenAPI spec). Upload once via
  `uploadAsset()` (`busybar-client.ts`), then reference it from an
  `AnimationElement` (`{type: "animation", path, loop: true, ...}`) — the
  device plays and loops it forever with no further requests. This is the
  right way to animate anything whose drawn shape changes between frames;
  see `nyan-cat`'s `rainbow` mode.

**Every draw clears the *entire* display first, not just the drawing app's
own prior elements.** `/api/display/draw` upserts elements by id rather than
replacing the scene, and — confirmed live against the device — a *different*
app's leftover draw can block a fresh one even at max priority, despite the
API spec claiming equal-priority + a different `application_name` should
override. `drawFrame()` and `runAnimation()` both clear unconditionally so
switching between apps never silently fails.

### Connecting over Wi-Fi or the internet instead

By default the app talks to `http://10.0.4.20` (USB). To target a device over
Wi-Fi or the internet, set `BUSYBAR_BASE_URL`:

```sh
BUSYBAR_BASE_URL=http://<busy-bar-ip-address> bun run hello-world
```

Wi-Fi and internet connections require authentication, which this app does
not yet send — see the [HTTP API docs](https://docs.busy.app/bar/dev/http-api)
for the `X-API-Token` (Wi-Fi) or `Authorization: Bearer` (internet) headers
you'd need to add.
